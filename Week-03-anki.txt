What makes a constructor different from a method?	The name matches the class, and there is no return type.<br><code>void Person(String name)</code> is a method. <code>new</code> does not call it.	week3 constructors
<pre>boolean ok = true;<br>void Bird() { ok = false; }</pre>What does <code>new Bird().ok</code> print?	<code>true</code>.<br><code>void Bird()</code> is a method. <code>new</code> uses the no-arg constructor the compiler added, and <code>ok</code> stays <code>true</code>.	week3 constructors
When does the compiler add a no-arg constructor, and what access does it have?	Only when you write no constructor at all. It has the same access as the class.<br>The first constructor you write removes that default. <code>new Account()</code> then fails unless one of your constructors takes no arguments.	week3 constructors
A class has only <code>Account(int cents)</code>. Does <code>new Account()</code> compile?	No. Writing <code>Account(int)</code> removed the default no-arg constructor.	week3 constructors
<code>int n = 5;</code> and <code>void set(int n) { n = 10; }</code>. What is the field after <code>set(10)</code>?	<code>5</code>.<br>The parameter hides the field. <code>n = 10</code> changes the parameter. <code>this.n = n</code> would store <code>10</code>.	week3 constructors
Where must <code>this(...)</code> sit in a constructor?	It is the first statement.<br><code>this(...)</code> calls another constructor of the same class. A statement before it does not compile.	week3 constructors
Does <code>Q(int n) { }</code> together with <code>Q() { this(n); }</code> compile, when <code>n</code> is an instance field?	No. <code>this(n)</code> reads the instance field before the object is built.<br><code>this(1)</code> compiles.	week3 constructors
<code>A() { this(1); }</code> and <code>A(int n) { this(); }</code>. What happens on <code>new A()</code>?	The code does not compile.<br>The constructors call each other. The compiler rejects that cycle. It is not a <code>StackOverflowError</code> at runtime.	week3 constructors
<pre>{ print "I" }<br>C() { this(1); print "A" }<br>C(int n) { print "B" }</pre>What does <code>new C()</code> print?	<code>IBA</code>.<br>The instance block and <code>C(int)</code> run in the constructor that builds the object. <code>A</code> prints after <code>this(1)</code> returns.<br>The same order with <code>X</code>, <code>Z</code>, and <code>Y</code> prints <code>XZY</code>.	week3 constructors
How many <code>public</code> top-level classes can one file have? Which modifiers can a top-level class use?	At most one. The file name matches that class.<br>A top-level class is <code>public</code> or package-private. <code>private</code> and <code>protected</code> are not allowed on it.	week3 constructors
What are the field defaults for <code>int</code>, <code>boolean</code>, <code>char</code>, and a reference, at the moment <code>new</code> allocates the object?	<code>0</code>, <code>false</code>, <code>'\u0000'</code>, and <code>null</code>.<br>Initializers and the constructor body run after those defaults. A local variable still has no default.	week3 constructors
Two <code>new Counter()</code> calls each do <code>made++</code>, and <code>made</code> is <code>static</code>. What prints?	<code>2</code>.<br>A <code>static</code> field is one variable for the class. Both constructors increment that same variable.	week3 order
Does <code>static void show() { System.out.println(n); }</code> compile when <code>n</code> is an instance field?	No. A <code>static</code> method has no object, so it cannot use <code>this</code> or an instance member.<br>An instance method can use a <code>static</code> member.	week3 order
For one class, what runs, and in what order, the first time it is used?	<code>static</code> fields and <code>static</code> blocks, top to bottom, once.<br>Then each <code>new</code> runs instance fields and instance blocks, top to bottom, then the constructor body.	week3 order
<code>main</code> is inside <code>Once</code>. Static marks are <code>S1</code> then <code>S2</code>. Each <code>new</code> marks <code>I1</code>, <code>I2</code>, <code>C</code>, and <code>main</code> prints a space between the two objects. What is the line?	<code>S1S2I1I2C I1I2C</code>.<br><code>S1S2</code> runs when the class loads, before <code>main</code> starts, so it is stuck to the first object. The second object prints <code>I1I2C</code> only.	week3 order
A class prints <code>S</code> in a static block, <code>I</code> in an instance block, and <code>C</code> in the constructor. What do two <code>new</code> calls print?	<code>SICIC</code>.<br><code>S</code> runs once. Each <code>new</code> adds <code>IC</code>.	week3 order
List the six initialization steps the first time a subclass is used.	1. Parent <code>static</code> fields and blocks.<br>2. Child <code>static</code> fields and blocks.<br>3. Parent instance fields and blocks.<br>4. Parent constructor body.<br>5. Child instance fields and blocks.<br>6. Child constructor body.	week3 order
<code>OrderLab</code> prints digits <code>1</code> through <code>8</code> for parent static, child static, parent field, parent block, parent constructor, child field, child block, child constructor. <code>main</code> does <code>new Child()</code>, a space, <code>new Child()</code>. What prints?	<code>12345678 345678</code>.<br>The second object starts at <code>3</code>. The static steps already ran.	week3 order
A subclass is constructed twice. What does the second <code>new</code> skip?	Both static steps.<br>The parent class and the child class are already loaded. Instance fields, instance blocks, and both constructor bodies still run.	week3 order
Which compiles, and what does the compiling version print?<pre>int a = b;<br>int b = 7;</pre><pre>int a = read();<br>int b = 7;<br>int read() { return b; }</pre>	The first does not compile. That is an illegal forward reference.<br>The second compiles and <code>a</code> is <code>0</code>. <code>read()</code> runs while <code>b</code> still has its default. <code>b = 7</code> has not run yet.	week3 order
A <code>final</code> instance field has no initializer. The constructor body never assigns it. Does the class compile? Can an instance block assign it?	The class does not compile. A blank <code>final</code> is assigned once on every constructor path.<br>An instance block may do that assignment. Assigning the same <code>final</code> a second time does not compile.	week3 order
<code>Parent</code> has only <code>Parent(int n)</code>. <code>Child()</code> has an empty body. Does <code>Child</code> compile?	No. Constructors are not inherited.<br>The compiler inserts <code>super()</code> because <code>Child()</code> does not start with <code>this(...)</code> or <code>super(...)</code>. <code>Parent</code> has no no-arg constructor, so the child must start with <code>super(n)</code>.	week3 order
Who can use a member marked <code>private</code>, package-private, <code>protected</code>, and <code>public</code>?	<code>private</code>: the declaring class only.<br>No modifier: the same package.<br><code>protected</code>: the same package, and subclasses.<br><code>public</code>: every class.	week3 encapsulation
Which class is encapsulated?<pre>class A { public int cents; }<br>class B { private int cents; public int cents() { return cents; } }</pre>	<code>B</code> only.<br><code>A</code> leaves the field open. <code>B</code> keeps <code>cents</code> private and reads it through a method.	week3 encapsulation
In the same file, <code>Box</code> has <code>int size = 2</code> and <code>private int secret = 9</code>. What does another class's <code>main</code> do with <code>box.size</code> and <code>box.secret</code>?	<code>box.size</code> prints <code>2</code>. No modifier means the same package, and the same file is the same package.<br><code>box.secret</code> does not compile. <code>private</code> stops every other class.	week3 encapsulation
Can a class's own <code>main</code> read that class's <code>private</code> field?	Yes. <code>private</code> allows the declaring class, including its <code>main</code>.<br>The ban applies to other classes.	week3 encapsulation
A <code>private final StringBuilder</code> starts as <code>&quot;a&quot;</code>. The getter returns that builder, and the caller does <code>append(&quot;b&quot;)</code>. What prints?	<code>ab</code>.<br>The getter handed out the same builder. <code>private</code> and <code>final</code> did not stop <code>append</code>. Return a copy when the stored object is mutable. A returned <code>String</code> is safe to share.	week3 encapsulation
<code>void setCents(int cents) { cents = cents; }</code> is called as <code>setCents(50)</code>. The field started at <code>0</code>. What does <code>cents()</code> return?	<code>0</code>.<br><code>cents = cents</code> assigns the parameter to itself. <code>this.cents = cents</code> would store <code>50</code>.	week3 encapsulation
A <code>BankAccount</code> starts at <code>100</code>. <code>deposit</code> adds only a positive amount. <code>withdraw</code> subtracts only a positive amount that fits. Call <code>deposit(40)</code>, <code>withdraw(25)</code>, <code>withdraw(1000)</code>. What is the balance?	<code>115</code>.<br><code>100 + 40 - 25</code> is <code>115</code>. <code>1000</code> is greater than the balance, so that withdrawal does nothing.	week3 encapsulation
What shape makes a class immutable?	The class is <code>final</code>. Every field is <code>private</code> and <code>final</code>. There is no setter.<br>A method that looks like a change returns a new object. A mutable field is copied on the way in and on the way out.	week3 immutable
<code>Shared</code> stores the caller's <code>StringBuilder</code>. <code>Copied</code> stores <code>new StringBuilder(name)</code>. Each caller then <code>append(&quot;b&quot;)</code> onto a builder that started as <code>&quot;a&quot;</code>. What prints?	<code>ab a</code>.<br><code>final</code> fixes the reference in the field. It does not freeze the builder that reference points at. The copy stays <code>a</code>.	week3 immutable
<code>Money</code> is <code>final</code>, with <code>private final int cents</code>. <code>plus</code> returns <code>new Money(this.cents + other.cents)</code>. Start from <code>100</code> and add <code>50</code>. What are the original and the result?	<code>100</code> and <code>150</code>.<br><code>plus</code> returns a new object. The original stays <code>100</code>.	week3 immutable
What does eligible for collection mean?	No live reference can reach the object, so the collector is allowed to reclaim it.<br>The exam asks about eligibility. It does not ask you to name the moment the collector actually runs.	week3 gc
<code>Object a = new Object(); Object b = a; a = null;</code> Before <code>main</code> returns, is the object eligible?	No.<br><code>b</code> still points at it. The object becomes eligible only when the last reference is gone.	week3 gc
<code>Object a = new Object(); a = new Object();</code> Which object is eligible?	The first object. Nothing points at it anymore.<br>The second object is not eligible, because <code>a</code> points at it.	week3 gc
Two nodes point at each other with <code>next</code>. Then both outside variables are set to <code>null</code>. Which nodes are eligible?	Both.<br>They still point at each other, and nothing outside points in. That is an island.	week3 gc
A method's local variable is the only reference to an object. The method does not store it anywhere. When is the object eligible?	After the method returns.<br>Inside the method the local variable still points at the object, so it is not eligible yet.	week3 gc
<code>static Object kept</code> is assigned in a method. The method also sets a local copy of that reference to <code>null</code>. After the method returns, is the object eligible?	No.<br>The local variable is gone. <code>kept</code> still points at the object. A <code>static</code> field keeps it reachable.	week3 gc
<code>kept</code> is a <code>static</code> field holding an object, and <code>main</code> calls <code>System.gc()</code>. What is true when <code>System.gc()</code> returns?	The object is still reachable through <code>kept</code>.<br><code>System.gc()</code> is a request. It does not make a reachable object eligible, and it does not promise that anything was collected.	week3 gc
<code>Object first = new Object(); Object second = new Object(); first = second;</code> Which object is eligible?	The first object.<br><code>first = second</code> drops the only arrow to the first box. <code>first</code> and <code>second</code> both point at the second box, so that box is not eligible.	week3 gc
